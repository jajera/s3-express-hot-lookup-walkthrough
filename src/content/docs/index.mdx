## Why this exists

Many services share a small set of keys that clients read constantly —
feature flags, pricing tables, session metadata. That is a
<Tooltip term="shared-hot-lookup" label="shared hot lookup" /> pattern: latency
and consistency matter more than multi-AZ durability for those hot objects.

<Tooltip term="s3-express" label="S3 Express One Zone" /> puts object storage
in a single Availability Zone next to your compute. You use a
<Tooltip term="directory-bucket" /> and session-based
<Tooltip term="create-session" label="CreateSession" /> auth so zonal GETs stay
in the single-digit millisecond range when the client is co-located.

<figure>
  <img src={hotLookup.src} alt="Same-AZ shared hot lookup: an m7g.large harness in a public subnet (apse2-az1) GETs identical hot keys from an Express directory bucket via CreateSession and from a Standard general-purpose bucket as the bakeoff baseline." />
</figure>

| | Standard general purpose | This lab (Express) |
| --- | --- | --- |
| Latency target | Good for most apps | Single-digit ms GET/PUT when same-AZ |
| Durability model | Multi-AZ | Single AZ (by design) |
| Auth for object ops | SigV4 as usual | CreateSession then zonal ops |
| Networking | Regional S3 endpoint | Regional + `s3express` gateway endpoint |
